# Selected Architecture A: implementation roadmap

Plan only. No phase is complete on the basis of this document. Architecture A selection is approved; [clarification gates](./requirements-clarification-log.md) must be resolved before affected behavior is implemented. Tests accompany each phase; phase 8 consolidates verification rather than postponing all tests until the end.

| Phase | Deliverables | Dependencies | Risks / gates | Planned verification | Completion criterion |
|---|---|---|---|---|---|
| 1. Maven and packages | One Java 21 Maven project, release 21, pinned dependencies, `ui.swing/application/domain/persistence.sqlite/receipt` packages, JUnit 5 runner | Approved A selection and design review | JDK mismatch, accidental server/module scope expansion | Maven compile/test discovery; domain free of Swing/JDBC dependencies | Reproducible build on documented JDK 21; no production feature claims |
| 2. Domain/Money/allocation | Encapsulated Money, participants, expense/policy/payment types and equal allocator | Phase 1 | Q-01 percentage rounding/tolerance, Q-06 dates; no artificial amount cap | T-01/02/03; exact sum/remainder and large decimal cases | Equal/invalid-input rules demonstrated; percentage branches only after policy approval |
| 3. SQLite adapters | Versioned schema, repositories, UnitOfWork, decimal TEXT mapping, foreign keys, unique source/operation keys, temporary DB fixtures | Domain contracts | Driver transaction protocol, busy handling, lost precision | T-08/09/11 using actual file DB and two connections | Exact round trips, rollback and uniqueness proven; migration/backup procedure documented |
| 4. Accounts and groups | Local login/hash adapter, membership roles/periods, direct-add/remove use cases | Phases 2–3 | Demo identity is not full FR-001; Q-13 manager continuity | T-04/05/12 and denied direct use-case calls | Local access and immediate member access tested; full email gate clearly labeled |
| 5. Expenses and approval | Submission/receipt linking/policy snapshot, single-step review, terminal-state guards | Phases 2–4 | Q-01/06/07/12; DB/filesystem recovery | T-06/07/08/10; stage/reject/approve and fault injection | No posting while pending/rejected; final approval atomic with phase 6 ledger capability |
| 6. Ledger and payments | Positive non-self posting factory, reverse payment entry, net balances, source reconciliation, operation-key results | Phases 3–5; final approval integration developed with phase 5 | Sign errors, source duplicates, Q-02 overpayments and Q-10 corrections | T-08/09/11; 12 debt minus 5 payment equals 7; concurrent retry/rollback | Approved shares/payments reconcile and apply once; gated policies remain explicit |
| 7. Swing integration | Views/presenters, navigation, field errors, clear review/debt direction, background work/EDT updates | Phases 4–6 | UI logic leakage, blocked EDT, errors hidden | T-15; slow adapter/manual flows, receipt permission checks | Local account→group→expense→review→payment flow works; unresolved features not falsely presented as available |
| 8. Verification and pilot review | Consolidated JUnit 5 suites, SQLite integration, manual UI records, traceability and measured balance latency | Phases 1–7 | Passing unit tests mistaken for complete acceptance | T-01–12/15/16, relevant AC/SC; record environment, failures and exclusions | Reviewed evidence for pilot subset; unresolved/undelivered full criteria remain incomplete |
| 9. Deferred full-product functions | Complete verification/reset, notices, ordered approvals, configurable reports and authorized corrections when specified | Policy decisions plus migration prerequisites | Q-01–10/12; reliable delivery/identity needs server authority | T-02/04/07/13/14/16 and full AC coverage | Each function accepted only with actual evidence; local prototypes are not production delivery |
| 10. Shared server/API and primary web | Central adapters/transactions/identity, controlled SQLite import, managed receipts, versioned HTTPS, browser UI; possible later Android/iOS | Phases 1–8; [migration strategy](./migration-strategy.md); phase 9 interleaved as required | Identity collisions, migration loss, security/hosting, reporting/notification operations | T-17, import reconciliation, restore/rollback drill and complete AC-010 browser acceptance | Primary web product accepted, data reconciled and security/operational ownership established; mobile separately scoped |

Phases 9 and 10 are planning tracks, not a requirement to ship production email/notifications on a local desktop before creating server infrastructure. Server foundations in phase 10 can precede production acceptance of phase 9 functions. Do not count local email simulation as completed delivery.

Each implementation review must record changed requirements/design IDs, tests actually run, observed output and remaining issues. Performance requires the specified 100-member/10,000-expense volume and at least 95% display within three seconds; filtered-report performance awaits reports. Usability requires observed participants and the original SC thresholds, not developer intuition. No commit is authorized by this roadmap.
