# Selected Architecture A: design decisions

Architecture A selection is owner-approved; detailed decisions below are documented designs, not implemented controls. Existing constitutional constraints are mandatory. New engineering refinements require human review; unresolved product behavior is separately tracked in the [clarification log](./requirements-clarification-log.md). See [ADR-C01](./architecture-decision-record.md).

| ID / decision | Rationale | Alternatives and consequences | Review status |
|---|---|---|---|
| D-01 Java 21 / Maven, single project | Constitution II and simple reproducible baseline | Other versions/build tools conflict; B's multi-module build adds initial overhead. Pin compiler/plugins/dependencies later. | Required baseline; build not verified |
| D-02 Swing local pilot | Constitution III and immediate project fit; no server needed | Web-first serves CR-009 sooner but does not supply requested desktop demonstration. Swing remains interim only. | Owner-approved choice; UI acceptance pending |
| D-03 Layered modular monolith | Encapsulate OO behavior and inward dependencies across eight feature packages | UI-driven rules couple tests; microservices and feature-layer artifact proliferation add unjustified complexity. One composition root wires ports. | Selected design; import/dependency checks pending |
| D-04 SQLite behind repositories | Low setup/deployment cost, local transactions | PostgreSQL/central server deferred. Decimal TEXT plus Java BigDecimal aggregation avoids REAL and fixed minor-unit integer caps; indexed queries need measurement. | SQLite approved; exact adapter mapping proposed for review |
| D-05 BigDecimal Money | Constitution V, currency scale and exact reconciliation | Float/double rejected. Equal remainder to payer confirmed; percentage residual/tolerance not decided. | Required; percentage policy gate unresolved |
| D-06 Append-only BalancePosting | Auditable effects and rebuildable balances; retain A | B's source-only view rejected. Expense participant→payer; payment payee→payer under debt semantics. More stored records require reconciliation. | Ledger selected; clarified sign convention for review/tests |
| D-07 Application authorization | GUI visibility is not an access boundary; removal must revoke access | UI-only checks rejected. Local host owners still can alter files; production authority later moves server-side. | Required behavior; controls not verified |
| D-08 Atomic UnitOfWork / operation keys | NFR-006 and source integrity across retries | Unique source lines plus terminal state guards; fingerprints reject key reuse with changed input. SQLite write reservation serializes writers; contention must be bounded/tested. | Engineering refinement proposed; driver protocol unverified |
| D-09 Managed receipt storage | Optional images without client paths in domain | DB BLOB storage could simplify atomic bytes but increases database size. Filesystem staging adds orphan/recovery handling. JPEG/PNG/size limits proposed, not approved product policy. | Storage boundary selected; limits unresolved |
| D-10 JUnit 5 / SQLite integration / manual UI | Constitution VI and executable business evidence | GUI-only tests insufficient. Test actual driver for decimal mapping/locking/rollback; staged acceptance distinguishes deferred features. | Required strategy; no tests executed |
| D-11 Maintained PlantUML | Constitution VII; components/classes/ERD/transactions/deployment | Static pictures alone cannot be maintained as source. Six files represent local pilot and labeled future components. | Sources created; rendering not verified |
| D-12 Future server/API migration | Preserve domain/services; eventually deliver primary web UI | Centralized B pilot deferred. Versioned HTTPS, server auth/repositories, exact DTOs and controlled import needed; client stacks undecided. | Future design direction, not MVP scope |
| D-13 Membership periods / immutable policies | Retain history on removal/rejoin and keep pending review meaning stable | Updating one interval loses history. Additional identity and active partial uniqueness required. Reviewer replacement/self-approval need product decisions. | Historical invariant required; refinement proposed |
| D-14 Notifications and reports later | Preserve CR-004/008 without expanding pilot | Durable outbox is a candidate after requirements clarification; direct delivery can couple provider failure to submission. Historical reporting requires date semantics. | Deferred; policy details unresolved |

No decision approves an overpayment policy, percentage rounding rule, transfer initiation, correction authorization or new customer scope. Existing A/B files remain original alternatives; canonical changes are explained in ADR-C01.
